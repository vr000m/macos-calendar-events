# Changelog

All notable changes to this project are documented here. Golden-file (`tests/golden/*.json`) changes always get a line.

Release rule: the `$id` in the packaged and `docs/schema/` schemas names the release tag that first shipped that schema content. Change the `$id` version only in a release that changes schema content, and run the `curl | cmp` check from the dev plan against that tag.

## Unreleased
### Added
- `macos-calendar-events` CLI: `window` (`--start`/`--end` as epoch seconds or RFC 3339 UTC, `--calendar`, `--pad-minutes`, `--include-notes`, `--prompt`), `calendars [--prompt]`, `schema {window-v1|calendars-v1}`, and `--version`. Exit codes 0–5 per the README contract.
- Python API: `events_in_window`, `list_calendars`, `authorization_status`, `request_access` (macOS 14+, read-only EventKit).
- JSON Schemas `window-v1` and `calendars-v1` (`schema_version` 1), packaged and published under `docs/schema/`.
- `scripts/validate_json.py` (paths and keywords only) and `scripts/regen_goldens.py`.
- CI guards `scripts/check_readonly.sh` (write-API denylist, the `scripts/eventkit_selectors.allow` selector allowlist, and the PyObjC import check `scripts/check_imports.py`) and `scripts/check_privacy.sh` (no real email addresses in the repository); `scripts/sync_schemas.py` copies the packaged schemas to `docs/schema/`.
- README: install with a pinned `--python`, Calendar permission walkthrough (terminal, launchd consumers, standalone launchd recipe, cron), interpreter caveats, subprocess integration rules, CLI and Python API examples, exit codes, known limitations.
- Golden files `tests/golden/window-v1.json` and `calendars-v1.json`, generated by `scripts/regen_goldens.py` and hand-reviewed (schema_version 1).
### Fixed
- All-day `start_date`/`end_date` use the Gregorian calendar. They followed the Mac's Calendar preference before, so a Buddhist-calendar Mac wrote `2568-11-19` for 2025-11-19.
- `scripts/check_privacy.sh` exits 2 when `git ls-files` fails. It passed with nothing scanned before.
- `window` exits 2 (was 1, `internal error`) for an oversized `--pad-minutes`, an end later than 9999-12-30T23:59:59Z (the last instant that still allows the one-day query margin), an epoch string of 4301 or more digits, and an epoch string with a trailing newline (the last was accepted). The Python API raises `InvalidQueryError` for the same end bound (it raised `OverflowError` before).
- `events_in_window(calendars="Work")` raises `InvalidQueryError`. It was read as one selector per character. `CalendarNotFoundError` can be pickled and copied.
- The CLI rejects abbreviated options (exit 2). `calendars --pro` used to prompt for access and `window … --i` used to include notes.
- A failed or incomplete stdout write (for example a reader that closed the pipe, or a full non-blocking pipe) exits 1 with one `internal error: <Exception>` line, `--help` and `--version` included. Before, it printed a traceback and exited 120, and under `python -u` it could exit 0 with no output. Bytes written before the failure stay on stdout, so use stdout only on exit 0 (README). `main()` called in-process with a text-only stdout (`redirect_stdout(io.StringIO())`) writes the same text instead of exiting 1.
- Calendar text holding an unpaired UTF-16 surrogate is written with U+FFFD in its place. The whole `window` or `calendars` command exited 1 before. A calendar whose id holds one can still be selected by title, by its listed id or by its exact EventKit identifier (EventKit is given the exact id).
- All-day dates follow a time zone change made while the process runs (Python API). The zone of the first query was kept before.
- `window_to_json` accepts and rejects windows exactly as `events_in_window` does (int epoch or aware UTC datetime bounds, `end > start`, the span cap and the year-9999 bound, else `InvalidQueryError`). It raised `AttributeError` for an int before. `request_access()` takes its default timeout from the same 60 s constant as the read gate.
- `scripts/validate_json.py` rejects `NaN`, `Infinity`, `-Infinity` and too deeply nested input as not JSON (exit 2; the last printed a traceback and exited 1). `scripts/check_privacy.sh` exits 2 when a file can't be read, and scans files with a newline in their name, a file named `-` (and the files listed after it) and binary files; it passed all four before.
- `scripts/check_readonly.sh` finds PyObjC imports by parsing the sources, so `import os, EventKit`, `x = 1; import objc`, continuation lines and `__import__("EventKit")` fail it, as does any module the PyObjC dependencies install (`Cocoa`, `CoreFoundation`, `PyObjCTools` included). Only the adapter's exact path is exempt.
- The schemas give the instant and `color_hex` patterns a `maxLength`, so validators where `$` also matches before a final newline (Python's) reject a trailing newline. Documents the CLI writes are unchanged.
- README: the integration example validates each document against the installed CLI's schema with `jsonschema`, with format checking (`jsonschema[format-nongpl]`) and `NaN`/`Infinity` rejected, and returns no hints for anything else (it returned events for `schema_version: true`, `events: [null]`, a `start` of `2025-02-30T12:00:00Z` and an extra `NaN` field); the Privacy section says `notes` is `null` without `--include-notes` (the key is always present); the window cap is labelled unverified at its full length.
### Changed
- Golden `tests/golden/window-v1.json`: added timed rows in Asia/Tokyo, Asia/Kolkata and Europe/Helsinki (Helsinki row selected only by padding) and all-day rows for each zone (local-midnight bounds, exclusive `end_date`). `calendars-v1.json` unchanged. Reviewed after the fact.
